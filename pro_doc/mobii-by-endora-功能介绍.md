# Mobii-by-Endora 总体功能介绍（偏业务）

> 面向：业务、产品、运营与交付干系人  
> 产品全称：**Mobii_Bidding_Platform_by_Endora**（下文简称 **Mobii-by-Endora**）  
> 一句话：在 **Endora Commerce** 开源电商能力之上，为「高端硬件 / 稀缺货 **竞价批采与配额分配**」做二次改造后的业务平台。  
> 本文同时写清两层能力：**① Endora 基座能力（复用）** + **② Mobii 竞价批采新增能力**。二者不可混称为同一套产品。

---

## 1. 产品定位

### 1.1 要解决什么问题

公司握有少量高端硬件（如 GPU H200 等）：**货少、意向客户多**。需要线上平台做到：

- 公平、可追溯地把稀缺货分给真实需求客户  
- 维护高端产品信息，并与大客户保持可运营的沟通与触达  
- 线上流程能对应运营 / 销售 / 售后责任人，与线下意向书、预付、发货对齐  
- 长期沉淀大客户订单，并为后续更多高端品类销售打底  

### 1.2 和常见「竞价」有何不同

| 维度 | 常见采购 / 招投标 | Mobii 本平台 |
| --- | --- | --- |
| 主导方 | 多为买方寻源、多供应商竞标 | **卖方握有稀缺库存**，多大客户竞争获取配额 |
| 目标 | 往往偏价低者得 | **真实需求优先 + 可履约 + 可追责** |
| 成交形态 | 常线上自动定标 | **人工审核 +（可选）法务 + 预付确认** 后才履约 |

因此业务形态是：**需求申报 / 密封意向 + 资格审核 + 竞争性分配**，而不是公开实时升价拍卖。

### 1.3 与 Endora 的关系（命名约定）

| 名称 | 含义 |
| --- | --- |
| **Endora 架构** | 上游开源平台 Endora Commerce 的既有架构与模块能力 |
| **Mobii-by-Endora** | 在 Endora 之上，为竞价批采做的改造蓝图与落地（**复用 + 扩展 + 新建竞价域**） |

- **不**用 Endora 的询价 RFQ（`quote_requests`）冒充竞价主路径  
- **新建** `bidding`（竞价）模块，订单 / 发货 / 组织等仍走 Endora 基座，并加上履约门禁

## 2. 谁用什么端（大B / 小b / 小c）

| 端 | 使用者 | 表面 | 职责（业务） | 阶段 |
| --- | --- | --- | --- | --- |
| **大B** | 平台管理员、运营、销售、售后、财务相关角色 | 管理后台 Admin | 规则、活动、审核、分配、预付确认、发货放行、货品与客户治理 | MVP 必做 |
| **小b** | 大客户组织采购账号 | 商城前台 Storefront | 注册准入、看活动、下载意向模板、提交密封回执、查看结果与状态 | MVP 必做 |
| **小c** | 移动端用户 | 小程序（规划） | 信息同步与通知；不做复杂提交 | Final，非 MVP |

**产品原则**

1. 大B 管规则、审核、责任人、发货放行；小b 管申报与结果查看。  
2. 小c 只做同步与通知，不做复杂提交。  
3. 内容（性能文案 / 视频 / 流程说明）服务「精准触达」，从属于货品与活动。

## 4. ① 基于 Endora Commerce 的基座能力（复用）

这些是 **Mobii 能跑起来的「电商与运营中台」底座**：竞价成交后的客户、货品、订单、钱、货、内容、权限，主要靠它们，而不是推倒重来。

### 4.1 组织、客户与账户

- **组织（Organization）** 作为大客户租户边界  
- 客户注册、资料、地址、成员邀请与角色  
- 登录、密码重置、双因素等账户安全  
- 支撑「谁可以看见 / 参与哪些竞价活动」的准入基础  

### 4.2 权限、管理员与审计

- 管理端用户、角色、细粒度权限（RBAC）  
- 敏感操作审计轨迹  
- Mobii 在其上扩展运营 / 销售 / 售后等角色种子与竞价权限码（见第 5 章）  

### 4.3 高端货品与内容触达

- **目录**：产品、变体、分类、属性、上下架与渠道可见性  
- **素材库**：图片 / 文档等数字资产  
- **CMS / 页面与内容**：性能说明、流程说明、图文视频等运营内容  
- 多语言、多销售渠道、搜索与 SEO（按部署启用）  
- 用于「把货品信息精准推给意向客户」，而不是另起一套 CMS 产品  

### 4.4 价格、库存与常规采购（次路径可保留）

- 价目 / 价格规则、库存数量与预留  
- 购物车、结账、（可选）询价 RFQ、快速下单、购物清单等  
- 在 Mobii 场景中：**竞价批采是主路径**；常规目录采购可作为次路径保留，不承担稀缺配额主流程  

### 4.5 订单、支付、发货与发票抽象

- 真实 **订单** 状态机、支付方式与收款事件  
- 发货单生命周期、退货等履约能力  
- 发票 / 文档模板等（按需要启用）  
- Mobii 的「中选转单 / 预付确认 / 发货门禁」**挂在这些基座之上**，而不是另造一套订单系统  

### 4.6 平台治理与集成

- 模块可安装 / 启用 / 停用  
- 设置中心、导入导出、事务邮件  
- API / API Key / Webhook，便于对接 ERP、财务、仓储等  
- 部署上可按 Mobii 实例裁剪无关模块

## 5. ② Mobii 竞价批采新增能力

相对 Endora 标准「加购结账 / RFQ」路径，Mobii **新建竞价域**，并强化角色分工与履约门禁。

### 5.1 功能域对照（相对 Endora 的处置）

| 功能域 | 主要能力 | Endora 基座 | Mobii 改造 |
| --- | --- | --- | --- |
| 权限角色 | 管理员 / 运营 / 销售 / 售后 | `admin_roles` 等 | 扩展角色种子与竞价权限 |
| 大客户 | 注册、资料、联系人、对接人 | 组织 / 客户模块 | 扩展对接人类型与联系人治理 |
| 高端货品 | 品类、库存、价、多媒体、说明 | 目录 + CMS + 素材 | 内容结构与挂载规范 |
| **竞价活动** | 发布、规则、客户范围、模板、截止 | （无对应主模块） | **新建 `bidding`** |
| **竞价回执** | 提交、附件、多级审核、预付 | 不可用 RFQ 冒充 | **新建于 `bidding`** |
| 分配与结果 | 中选 / 落选、通知、转订单 | 订单可复用 | **分配结果 + 转订单缝** |
| 资金确认 | 预付应收 / 实收 | 支付抽象 | 金额校验 + 确认门禁 |
| 发货售后 | 发货、验货、责任人 | 发货模块 | **G-S\* 发货前置清单** |
| 审计追溯 | 操作人、状态、交易编号 | 审计日志 | 签核节点强制可追溯 |
| 通知 | 活动 / 状态通知 | 邮件等 | MVP 可用邮件；小c Final |

### 5.2 大B：竞价活动（Campaign）

运营可创建并发布「某硬件产品 — 竞价业务」活动，典型包括：

- 关联货品 / 品类、可分配数量（配额）  
- 可见客户范围（准入组织 / 客户类型）  
- 规则：最低价、数量上限、预付比例或固定预付等（**以发布时规则版本为准**）  
- 意向竞价单模板（供小b 下载填写后回传）  
- 截止时间；截止后禁止新回执 / 改价  

**活动主状态（业务）**  

`草稿 → 已发布(开放投递) → 已截止(评审中) → 已分配(公布结果) → 已关闭`  
旁路：`已取消`（记操作人与原因）。

### 5.3 小b：密封回执 / 意向单（BidReceipt）

大客户侧典型动作：

1. 看到对其开放的活动  
2. 下载意向模板 → 填写 → 上传 PDF（或结构化字段 + 盖章件）  
3. 提交密封回执（评审结束前 **不可见同行报价明细**）  
4. 查看本人回执状态与最终中选 / 落选结果  

**回执主状态（业务）**  

`已提交 → 运营审核中 → 销售确认中 → [法务确认中] → 待预付 → 预付已确认 → 已中选待履约 → 已转订单`  
旁路：`已驳回` / `已撤回` / `已落选` / `已逾期取消`。

### 5.4 大B：多级签核、分配、预付与转订单

- **运营核对 + 销售确认**（法务确认可配置为必选）  
- 每步签核记人、记时、记前后状态（禁止只靠备注）  
- **分配**：记录中选 / 落选；配额与库存锁定一致，超额拒绝  
- **预付确认**：实收须与规则算出的应收一致，否则不可进入可履约  
- **转真实订单**：中选且预付确认后，生成 Endora 订单，并保留 **唯一交易编号**，串联：活动 → 回执 → 意向附件 → 收款 → 订单 → 发货  

### 5.5 履约门禁（钱货人一致）

相对 Endora「有订单即可往下走」，Mobii 对竞价关联履约增加硬门禁，例如：

| 类型 | 要点（业务语言） |
| --- | --- |
| 客户 / 回执侧 | 未准入不可投；附件必填；截止强制；密封；中选后须采购承诺才履约 |
| 审批 / 资金侧 | 多角色签核；预付未确认不可建可履约单或不可发货；金额不一致阻断 |
| 发货 / 追溯侧 | 回执通过 + 附件在档 + 款项确认 + 库存锁定齐了才可发货；售后（或授权角色）发货；责任人全程可查；落选 / 逾期释放库存 |

**发货硬规则**：未满足发货前置清单，不得进入「已发货」。

### 5.6 角色分工（相对通用后台的强化）

| 角色 | 典型职责 |
| --- | --- |
| 平台管理员 | 系统与权限总控 |
| 运营 | 活动维护、回执初审、分配 |
| 销售 | 对接客户、回执确认（大额设备需人工线下确认） |
| 售后 | 发货、验货（与销售 / 运营权限分离） |
| 财务相关权限 | 预付到账确认（金额校验） |

组织侧还可维护 **对接负责人**（运营 + 销售 + 售后），保证大客户有人对口。

## 6. 端到端业务故事（两层能力如何串起来）

### 故事：稀缺 GPU 配额分配到发货

1. **基座**：大客户完成组织注册与准入；货品在目录 / CMS 中维护好参数与说明。  
2. **竞价新增**：运营在大B 发布竞价活动（规则、配额、模板、截止、可见客户）。  
3. **竞价新增**：小b 下载意向书、上传并提交密封回执。  
4. **竞价新增**：运营审核 → 销售确认（+ 可选法务）→ 分配中选 / 落选。  
5. **竞价新增 + 基座支付**：财务确认预付金额匹配。  
6. **竞价新增 → 基座订单**：中选回执转成真实订单，写入交易编号。  
7. **竞价门禁 + 基座发货**：清单通过后，售后创建发货；全程可查责任人与审计。  
8. **异常路径**：驳回、逾期、落选 → 释放配额 / 库存；未付款不可发货。  

### 次路径（可选）：常规批采 / 标价采购

同一小b 前台仍可浏览目录、走 Endora 常规加购或询价（若模块开启）。  
**稀缺货主成交路径以竞价活动为准**，避免两套规则抢同一配额。

## 7. 首页与导航的业务侧重（小b）

小b 体验上以 **竞价批采为主、常规采购为次**（与本仓库前台改造一致）：

- 主入口：竞价活动中心、我的回执 / 结果  
- 次入口：常规采购品类 / 目录（服务非稀缺或后续品类拓展）  

大B 侧在通用运营能力之外，增加竞价活动台、回执审核台、分配与转单相关操作。

---

## 8. 明确不做 / 非主路径（避免误解）

| 项 | 说明 |
| --- | --- |
| 公开实时升价拍卖引擎 | 非本产品形态 |
| 用 RFQ 冒充竞价主流程 | 禁止；RFQ 最多作旁路 |
| 小程序复杂提交（小c） | Final 阶段；MVP 不做 |
| 把 Endora 与 Mobii-by-Endora 混称为同一产品架构 | 禁止；对外介绍应同时说清基座 + 竞价增量 |

## 9. 总结（给干系人的一页口径）

**Mobii-by-Endora = Endora 电商运营基座 + 稀缺货竞价批采域。**

- **基座解决**：客户组织、货品内容、权限审计、真实订单与收发货、可集成可裁剪的中台。  
- **增量解决**：活动规则与密封意向、多角色签核与分配、预付与发货硬门禁、交易全链路可追责。  
- **价值主张**：货少人多时，把配额分给真实可履约客户，并让线上状态与线下意向书 / 预付 / 发货责任人对齐。
