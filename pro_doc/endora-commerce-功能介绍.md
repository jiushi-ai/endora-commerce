# Mobii_竞价批采平台 总体功能介绍（偏运营业务方向描述）

> 面向：业务、产品、运营与交付干系人  
> 目的：用业务语言说明「这套线上系统能做什么、给谁用、覆盖哪些核心场景」  
> 说明：本文描述 **Mobii_竞价批采平台（Mobii_Bidding_Platform）** 的完整业务能力全景。

---

## 1. 平台定位

**Mobii_竞价批采平台** 是一套同时服务 **B2B（企业采购）** 与 **B2C（个人购买）** 的线上商务平台：同一套系统里既可「直接下单购买」、走「询价报价（RFQ）」，也可对稀缺高端货品走「**竞价批采**」（密封意向申报 → 多角色审核 → 配额分配 → 预付确认 → 转订单履约）；客户按 **组织（公司）** 管理，支持多账号角色、信用额度结算；运营侧有权限化后台，对外提供 API / Webhook，便于对接 ERP、PIM、WMS、CRM 等系统。

---

## 2. 三类-运营角色

| 角色 | 主要入口 | 典型诉求 |
| --- | --- | --- |
| 买家 / 采购方（大客户） | 商城前台（Storefront） | 查商品、比价、加购、询价；参与竞价活动、下载意向模板、提交密封回执、查看中选结果；下单、查订单与发票、管理组织成员与地址 |
| 运营 / 销售 / 财务 / 售后 | 管理后台（Admin） | 管目录与价格；发布与管理竞价活动；审核回执、分配配额、确认预付、转订单；处理询价与订单、发货退货、促销内容、客户与信用额度、权限与审计 |
| 系统 / 集成 | API + Webhook + 连接器抽象 | 与外部 ERP/PIM/支付/物流等同步，不把业务锁死在单一厂商 |

## 3. 三端-产品运营入口

- **商城前台**：面向客户的网站（可 SSR），覆盖注册登录、商品浏览与搜索、购物车结算、询价、**竞价活动中心与我的回执**、账户与组织中心等；首页以竞价批采为主入口、常规采购为次入口。
- **管理后台**：面向平台运营团队，按权限控制菜单与操作（运营 / 销售 / 售后等职责可分离）；支持命令面板（⌘K / Ctrl+K）快速跳转与执行动作；含竞价活动台、回执审核台、分配与转单等能力。
- **开放接口层**：REST API（可导出 OpenAPI）、API Key、出站 Webhook；业务能力按「模块」安装或关闭。

## 4. 核心业务能力（按业务域）

### 4.1 商品与目录

- 产品、规格变体、分类、属性、素材库
- 按 **销售渠道**、语言维护展示内容
- 支持自定义字段，满足行业特有信息（如高端硬件参数、安装与售后说明）而不必改表结构
- 前台搜索（含全文检索能力）、商品对比、SEO（元信息、站点地图等）
- 可为竞价活动关联货品 / 品类，并挂载多媒体与流程说明内容

### 4.2 价格、税与促销

- **价格本 / 价目表**：可按币种、目录、买家组织、销售渠道等规则决定「谁看到什么价」
- 税率解析（国家 / 商品类型 / 增值税身份等）
- 购物车级促销：折扣比例、减免金额、免运费等，并可设适用条件
- 竞价活动可单独配置规则口径（如最低价、数量上限、预付比例或固定预付等），以活动发布时的规则为准

### 4.3 客户、组织与账户

- **组织（Organization）** 是多租户业务边界：B2B 公司账户、B2C 个人组织均可
- 组织注册、邀请成员、角色分工、地址簿；可维护大客户资料、线下联系人与平台对接负责人（运营 / 销售 / 售后）
- 客户生命周期、销售代表归属；支持按组织准入控制「谁可见 / 可参与」指定竞价活动
- 登录、密码重置、双因素认证（2FA）等账户安全能力

### 4.4 采购路径：直购 + 询价 + 竞价批采 + 采购辅助

平台支持 **多条并行成交路径**：

| 路径 | 适用场景 | 业务结果 |
| --- | --- | --- |
| 直购（购物车 → 结账 → 订单） | 标价清晰、可立即购买 | 生成订单并进入履约 |
| 询价 RFQ（报价请求） | 大单、不定价、需销售报价 | 草稿 → 报价 → 接受/拒绝 |
| **竞价批采（活动 → 密封回执 → 审核分配）** | **货少客多的稀缺高端货；需真实需求与可履约优先** | **申报 → 运营/销售（+可选法务）审核 → 中选/落选 → 预付确认 → 转订单履约** |
| 快速下单 | 熟客按 SKU / CSV 批量点货 | 加速复购 |
| 购物清单 | 常购组合、项目备料 | 可一键转购物车或转询价 |

**竞价批采要点（业务）**

- 大B 发布活动：货品与配额、可见客户范围、规则版本、意向单模板、截止时间  
- 小b 下载模板 → 填写 → 上传附件后提交；截止后不可新投 / 改价；评审结束前同行报价默认密封  
- 回执多角色签核（至少运营 + 销售）；分配中选 / 落选；配额与库存锁定一致  
- 中选后确认预付（实收须匹配规则应收）再转真实订单；一笔成交保留唯一交易编号，串联活动、回执、附件、收款、订单、发货  

### 4.5 订单、支付与信用

- 下单、订单状态流转，关联支付与配送方式
- 支付方式可配置；提供银行转账、自提、**信用额度**等抽象（在线卡支付网关可按部署对接）
- **信用额度**：授信、占用与释放，适合账期客户
- **竞价成交**：支持预付 / 定金确认；未确认到账或金额不符时，不可进入可履约或不可发货
- 支付驱动与结算事件可扩展，便于后续接网关

### 4.6 库存、发货、退货与发票

- 库存数量、预留、到货通知；竞价分配与库存锁定联动，超额分配系统拒绝；落选 / 逾期 / 取消可释放库存
- 配送方式配置；发货单生命周期（与支付侧对称的履约记录）
- **竞价关联订单的发货前置清单**：回执通过、意向附件在档、款项确认、库存锁定等齐备后方可发货；发货权限与销售 / 运营职责可分离（售后或授权角色）
- 退货 / 投诉（RMA）：提交、审核、逆向物流与结算
- 发票 / 形式发票 PDF、发票台账与编号等抽象（具体报税对接可按地区扩展）
- 支持客户意向书等文档模板与回执附件归档，便于与线下法务 / 合同流程对齐

### 4.7 内容、营销与触达

- **CMS 页面搭建**：页面、区块、模板，按渠道与语言发布
- 博客 / 内容运营、可配置巨型导航（Megamenu）
- 邮件模板与事务邮件、自有邮件营销（订阅、标签、分群、活动与自动化）；可用于竞价活动与回执状态通知
- 文档模板（对比单、发票、报价单、**意向竞价单** 等 PDF 版式可在后台设计或下发）
- 商品 Feed（向购物/广告平台推送）、GA / GTM / Meta / LinkedIn 等投放与分析埋点
- 高端货品可配套性能图文、视频、安装说明、售后规则与流程说明，服务精准触达

### 4.8 销售协同与内部协作

- **CRM 销售机会**：可配置状态流，并与订单联动
- **项目与任务**：跨组织项目阶段、管理员待办与截止日期
- **竞价审核协同**：运营核对、销售确认、可选法务节点；每步记人、记时、记状态，责任人全程可追溯
- 管理端全局搜索、通知、操作审计

### 4.9 平台治理与扩展

- 多 **销售渠道**、多币种、多语言
- 管理员、角色、细粒度权限（含竞价活动读写、回执审核、预付确认、分配、发货等相关权限）；敏感操作审计；可模拟登录（impersonation）做客服排查
- 模块可安装 / 启用 / 停用：停用不等于删数据，可逆
- 导入导出（CSV）、设置中心、凭证配置（如邮件/LLM 适配器）
- ERP / PIM 连接器抽象层 + Webhook，方便与现有信息系统对接
- PWA：可安装、缓存与更新策略等渐进式体验能力

## 5. 典型业务故事（端到端）

### 故事 A：企业客户按价目表直购

1. 采购员加入公司组织并登录前台  
2. 按组织价目表看到专属价格，搜索或快速下单加入购物车  
3. 选择配送与支付方式（含信用额度）完成结账  
4. 运营在后台确认订单 → 发货 → 开具发票记录  

### 故事 B：大单询价成交

1. 客户在商品页发起「询价」或从购物清单转 RFQ  
2. 销售在后台认领、报价或拒绝  
3. 客户接受报价后进入订单履约  
4. 全程可按权限查看与审计  

### 故事 C：稀缺货竞价批采成交

1. 大客户组织完成注册与准入，登录前台  
2. 运营发布竞价活动（货品、配额、规则、意向模板、截止与可见客户）  
3. 客户下载意向书、上传附件并提交密封回执  
4. 运营审核 → 销售确认（+ 可选法务）→ 分配中选 / 落选  
5. 财务确认预付金额匹配后，回执转真实订单（保留交易编号）  
6. 发货前置清单通过后，售后发货；驳回 / 逾期 / 落选则释放配额与库存  

### 故事 D：运营上新与多渠道运营

1. 在后台维护商品、分类、渠道可见性与价格本  
2. 用 CMS / 博客 / 导航更新前台内容（含高端货说明与流程页）  
3. 配置促销、SEO、商品 Feed 与广告像素  
4. 不需要的模块在后台关闭，不影响其余业务

## 6. 开源能力边界（业务视角）

以下能力在平台中以 **抽象与流程** 提供，具体「对接哪家支付、哪家快递、哪国电子发票」通常通过扩展模块或自研适配完成：

- 在线卡支付 / 钱包 / 本地快捷支付网关  
- 快递面单、柜机选点等承运商深度集成  
- 财务总账 / 报税通道的完整落地（如特定国家电子发票直连）  
- 特定品牌 PIM 的开箱即用同步包  

也就是说：**买卖、询价、竞价批采、组织、价格、订单、库存、内容与集成「骨架」齐全**；与本地支付、物流、财税厂商的「最后一公里」可按部署需要叠加。

## 7. 业务侧重说明（可选阅读）

本系统同时具备通用电商成交能力与稀缺货竞价批采能力。对高端硬件等「货少客多」场景，**竞价批采**是主成交叙事：卖方配额分配、密封意向、人工审核与预付门禁优先于「纯抬价拍卖」或「仅价低者得」。

常规直购与询价仍可用于标价清晰或非稀缺品类；同一客户组织可按业务需要选用不同路径，配额类货品以活动规则与审核结果为准，避免多路径抢占同一库存。

## 8. 总结

Mobii_竞价批采平台 对企业侧的价值可以概括为五点：

1. **一种系统服务多种成交方式**：标价直购、询价报价与稀缺货竞价批采并存  
2. **以组织为中心的 B2B 运营**：成员、角色、地址、信用额度、专属价格与活动准入  
3. **竞价全链路可追责**：活动规则、密封回执、多角色签核、预付确认、转订单与发货门禁  
4. **从获客内容到履约售后的闭环**：目录、营销、订单、库存、发货、退货、发票  
5. **可开关、可对接、可按部署扩展**：模块化启停 + API/Webhook + 连接器抽象
