### 3. 按波 cherry-pick（merge 提交用 `-m 1`）

```bash
# —— 波 1a ——

git cherry-pick -m 1 72d0839f4   # WP-02a #701
git cherry-pick -m 1 f42bbd517   # WP-02b #703

# —— 波 1b / 1c ——

git cherry-pick -m 1 7806c791f   # WP-08 #706 admin-ui

# —— 波 1d ——
git cherry-pick -m 1 b6f90e547   # WP-10 #713 commerce
# 若 WP-10 把商品卡/购物车一并带入且冲突过大：
# abort 后改为路径级取出 organization-permissions / commerce-permissions /
# getCommerceAbilitiesAction / shopping-lists 门控，手工接线（保留本仓 i18n）
```

某一 pick 冲突时：

```bash
git status
# 原则：170 角色/permissions/守卫 → 上游；zh-CN/zh-TW、Mobii、167/168/#85 → 保留本地
git add <已解决文件>
git cherry-pick --continue
# 放弃本次：git cherry-pick --abort
```

缺对象时：

```bash
git fetch upstream '+refs/heads/master:refs/remotes/upstream/master'
```

**备选（冲突过多时）：** 对单个 WP 使用 `cherry-pick -n -m 1` 摊平后再一次提交；或对该 WP 做路径级 `checkout upstream/master -- <paths>`——仍优先按 WP merge 顺序，便于回退。

**不推荐本阶段：** 一次 `git merge af252f7e2`（整 PR #736）——冲突面接近整 feature，难按波回退。
