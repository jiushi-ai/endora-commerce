## 推荐操作步骤（对齐上次 168 cherry-pick）

### 0. 工作区干净 + 备份点

```bash
cd ~/github/endora-commerce
git status
# 有未提交改动先 commit 或 stash
```

### 1. 确认 upstream 并 fetch

```bash
git remote -v
# 若无 upstream：
# git remote add upstream https://github.com/endora-commerce/endora-commerce.git

git fetch upstream master
```

### 2. 从当前主线拉分支（勿直接在 master 试）

```bash
git checkout master
git pull origin master   # 若需要
git checkout -b feat/storefront-167-from-upstream
```

### 3. Cherry-pick 167 核心提交（不要 pick merge 提交 `bef6c41f0`）

按依赖顺序（与上次「只 pick 功能提交」同思路），建议顺序：

```bash
# 1) 渠道字段 + 迁移 + urlLanguages
git cherry-pick 5cf606ab2

# 2) Admin 表单勾选 Prefix…
git cherry-pick b018c53b0
# （若有）0825f62a0 测试可一并 pick

# 3) storefront middleware / locale-path / 链接改造（最大一块）
git cherry-pick 3b8dc9ad9

# 4) 切换器改为「同页多语链接」Tab
git cherry-pick 4ae1395bb

# 5) 平台 schema 发布迁移（若 5cf606 后仍缺）
git cherry-pick bf2c938e5

# 6) 后端发出的店面链接带语系前缀
git cherry-pick d118abe60

# 7) SEO / sitemap / hreflang（若要与 demo 行为一致，建议带上）
git cherry-pick 78c68252c
git cherry-pick 5ff1ef1c3

# 8) CMS slug 不与语系前缀冲突
git cherry-pick 646939426

# 9) 文档/changeset（可选）
git cherry-pick 61fc32160

# 10) 合入后的小修复（建议）
git cherry-pick 5e0c2b4a7
git cherry-pick bdfb49242
```

某一 pick 冲突时：

```bash
git status
# 手工解决；原则：167 的 URL/切换器逻辑用上游；Mobii 品牌/zh 文案/竞价/168 NavigationBar 保留本地
git add <已解决文件>
git cherry-pick --continue
# 放弃本次：git cherry-pick --abort
```

若一次 pick 缺对象：

```bash
git fetch upstream '+refs/heads/master:refs/remotes/upstream/master'
```

**备选（冲突过多时）：** 用 `git cherry-pick -n` 把多提交打成一摊再一次提交，或对「仅 sales_channels + storefront i18n + middleware」做路径级 checkout——仍建议优先按上面顺序 pick，便于回退。

| 文件/主题 | 处理 |
|-----------|------|

| 你们的 `localized-link` 透传 shim | **换成**上游真实 `locale-path` + `LocalizedLink` |

### 5. 本地验证（先于 ECS）

