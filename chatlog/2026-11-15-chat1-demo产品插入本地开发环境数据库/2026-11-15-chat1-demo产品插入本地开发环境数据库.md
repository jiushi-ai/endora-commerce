## 结论：先跑 `temp/*.sh`，更快更安全

| 方案 | 适合何时 | 成本 |
|------|----------|------|
| **A. `temp` 下 seed 脚本**（推荐现在用） | 本地要测目录/PDP/购物车/结算，有几个样例商品就行 | 几分钟，走 Admin API |
| **B. 从 ECS `pg_dump` 整库导入** | 要复现生产订单、组织权限、渠道绑定等完整状态 | 半小时～更久，且有风险 |

你当前是 `pnpm run dev` + 本地空库，目标是有数据可测结算页流程 → **A 更合适**。

---

## 为什么不优先整库导入

可以做（SSH 隧道 + `pg_dump`/`pg_restore`），但通常更麻烦：

1. 生产可能有真实客户/密码哈希/会话，不宜当日常开发库  
2. 本地 schema/migration 若与生产不完全一致，restore 易失败  
3. 媒体文件在对象存储，光导库商品图仍可能缺  
4. 仍可能缺你刚排查的「渠道 ↔ 配送/支付」等配置，下单照样灰  

整库更适合「线上复现某个具体 bug」，不是日常补商品。

## 推荐操作（本地）

`temp` 脚本是 **Admin API 建商品+价格**，不是直插 SQL。把 `API_BASE` 指到本地即可：

```bash
# 先确认本地 backend 已起来（pnpm run dev），且能 admin 登录
export API_BASE='http://localhost:3001'   # 按你本地 API 端口改
export ADMIN_EMAIL='463668442@qq.com'
export ADMIN_PASSWORD='111111aaaaaa'

cd "/home/eden/github/endora-commerce/temp/H200 GPU _ NVIDIA"
bash seed-h200-on-ecs.sh

cd "/home/eden/github/endora-commerce/temp/金士顿（Kingston）FURY 16GB DDR4 3200 C16 台式机内存条"
bash seed-kingston-fury-on-ecs.sh
# 其余 Z11 / Adlink / ETFE 同理，需要几个跑几个
```

脚本默认 `API_BASE=https://api.justgoai.com`，**不改就会打到生产**，本地一定要先 `export API_BASE=...`。

若本地还是空壳，先保证：

```bash
pnpm run setup   # 或你们平时的 db:fresh + module:install
# 再 pnpm run dev
```

否则 API 登录/建商品会失败。
